# Learnshift Setup Guide

Setup instructions for the **Learnshift** AI-Powered Personalized Learning Platform.

**Stack:** React 18 + TypeScript (Vite) frontend, Laravel 12 REST API backend, Supabase (PostgreSQL) database + storage, Mistral AI for AI features.

---

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Node.js | v18+ | Required for the Vite frontend |
| npm | 9+ | Ships with Node.js |
| PHP | 8.2+ | Required for the Laravel backend |
| Composer | 2.x | PHP package manager |
| Supabase account | — | PostgreSQL DB + Storage buckets |
| Mistral AI API key | — | Chat completions + embeddings |

---

## 1. Clone the Repository

```bash
git clone https://github.com/<your-org>/Learnshift.git
cd Learnshift
```

---

## 2. Frontend Setup (React / Vite)

```bash
# From the repo root
npm install
```

The frontend runs on `http://localhost:5173` and talks to the backend on `http://localhost:8000/api`.

### Frontend Environment

The frontend uses hardcoded Supabase credentials in `src/lib/supabase.ts`:

- `SUPABASE_URL` — your Supabase project URL
- `SUPABASE_ANON_KEY` — your Supabase anon key
- `SUPABASE_SERVICE_ROLE` — your service-role key (used for direct DB/Storage access)

Update these three constants to point at your own Supabase project. Do **not** commit the service-role key.

The backend base URL is set in `src/lib/api.ts:3` (`http://localhost:8000/api`).

## 3. Backend Setup (Laravel)

```bash
cd backend

# Install PHP dependencies
composer install

# Create the .env file from the template
cp .env.example .env

# Generate the app encryption key
php artisan key:generate

# Run database migrations and seed demo data
php artisan migrate:fresh --seed
```

### Backend Environment (`.env`)

Minimum required settings:

```
APP_NAME=Learnshift
APP_URL=http://localhost
APP_KEY=                          # generated by php artisan key:generate

DB_CONNECTION=pgsql
DB_HOST=<supabase-host>.pooler.supabase.com
DB_PORT=5432
DB_DATABASE=postgres
DB_USERNAME=postgres.<your-project-ref>
DB_PASSWORD=<your-password>
DB_SCHEMA=public

# Storage (Supabase S3-compatible)
FILESYSTEM_DISK=s3
AWS_ACCESS_KEY_ID=<supabase-storage-access-key>
AWS_SECRET_ACCESS_KEY=<supabase-storage-secret-key>
AWS_DEFAULT_REGION=auto
AWS_BUCKET=learnshift
AWS_ENDPOINT=https://<project-ref>.supabase.co/storage/v1/s3
AWS_USE_PATH_STYLE_ENDPOINT=true

# Queue (required for content ingestion jobs)
QUEUE_CONNECTION=database

# AI Provider (Mistral)
AI_PROVIDER_CHAT=mistral
AI_PROVIDER_EMBEDDING=mistral
MISTRAL_API_KEY=<your-mistral-api-key>
MISTRAL_MODEL=mistral-small-latest
MISTRAL_VISION_MODEL=pixtral-12b-2409
MISTRAL_EMBEDDING_MODEL=mistral-embed
```

## 4. Database Setup (Supabase)

Two options — the Laravel migrations, or the raw SQL scripts.

### Option A: Supabase SQL Scripts (recommended for RLS)

1. Create a Supabase project.
2. Open the **SQL Editor** in the Supabase dashboard.
3. Run `database/full_setup.sql` — this creates all tables, RLS policies, triggers, and the storage bucket.
4. For the Supabase-native `profiles` trigger / storage fixes, also run the files in `database/` as needed:
   - `fix_schema.sql`
   - `fix_rls_policies.sql`
   - `fix_profiles_table.sql`
   - `supabase_storage_fix.sql`

### Option B: Laravel Migrations

With `DB_CONNECTION=pgsql` pointing at Supabase, run:

```bash
php artisan migrate:fresh --seed
```

**Note:** RLS policies are not created by the Laravel migrations — apply the SQL scripts from `database/` if you need Row-Level Security.

## 5. Running the App

### Terminal 1 — Backend API

```bash
cd backend
php artisan serve --port=8000
```

### Terminal 2 — Queue Worker (required for AI ingestion / captioning jobs)

```bash
cd backend
php artisan queue:listen --tries=1 --timeout=0
```

### Terminal 3 — Frontend

```bash
# From the repo root
npm run dev
```

Then open `http://localhost:5173`.

## 8. Troubleshooting

**CORS errors in the browser** — the backend allows `http://localhost:5173` (`backend/config/cors.php`). Make sure the Vite dev server runs on 5173.

**401 "credentials incorrect"** — confirm the user is `is_active = true` and the email/password match a seeded account.

**AI features return errors** — verify `MISTRAL_API_KEY` is set and the queue worker is running (`php artisan queue:listen`).

**File uploads fail** — check the S3/AWS env vars and that the `learnshift` storage bucket exists in Supabase.

**403 on signup** — signup is intentionally disabled on the backend; accounts are created by admins (see `/admin/account-generation`).
